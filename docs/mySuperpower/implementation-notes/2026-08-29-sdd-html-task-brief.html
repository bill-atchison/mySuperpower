Task 1 — Pin extensionless skill scripts to LF · 562df1c

The guarantee was a side effect, not a rule

git ls-files --eol confirmed the defect before the change: all three SDD scripts read i/lf  w/crlf  attr/ — LF in the index, CRLF in the working tree, and no attribute governing them. Since the build copies from the working tree, dist/ inherited CRLF; the released blob only came out LF because core.autocrlf re-normalized it inside the publish worktree. A publishing machine with core.autocrlf=false would have shipped a CR-terminated shebang.

Both rules were needed. skills/**/scripts/* covers the published location; overlays/**/scripts/* covers a fork-owned script at its source location, which is where the build reads from — a rule on skills/ alone would let a CRLF working copy flow straight into dist/.

No upstream file content changed. The index blobs were already LF, so git add --renormalize . staged nothing but .gitattributes; the delete-and-checkout only re-materialized the working tree under the new attribute. That was the check that mattered, and it passed.

Task 3 — The overlay files capability · 5df19ed

Deviation — the collision check had to move above the existence check

The plan ordered these as existence-then-collision. Running the tests showed why that is wrong: each entry is copied as it is validated, so by the time a duplicate to is reached, its twin is already on disk. The existence check fired first and reported a same-build collision as “already exists in dist; overlays must not replace upstream files” — naming the wrong problem, and pointing at a file the build had written itself moments earlier.

Swapping them makes both diagnoses accurate: a duplicate reports a collision naming the entry it clashes with, and only a genuine pre-existing upstream file reports the replace-refusal. Fixed in the implementation; the plan text still carries the original order.

Deviation — the test’s placeholder collided with the key it sat inside

All seven schema cases failed with The property 'skill' cannot be found on this object. PowerShell’s -replace is case-insensitive by default, so the 'SK' placeholder matched the sk in the key "skill" and renamed the property to subagent-driven-developmentill. Fixed with non-colliding @@SKILL@@/@@ABS@@ tokens and case-sensitive -creplace; the absolute path also needs its backslashes doubled for JSON.

Worth recording how this was caught: the cases reported “failed for the wrong reason”, not a bare failure. An earlier draft of this test accepted any nonzero exit, and under that version all seven would have reported ok here while proving nothing about the rules they name.

The destructive-path guards fired correctly on first run

All three — OutDir as the repository, as an ancestor, and nested with lowercased casing — passed immediately, and each asserts the fake root still exists afterwards. They run against a throwaway copy of the build script whose $root is a temp directory, so a missing guard destroys scratch space rather than the working copy.

Before — existence checked first

if (Test-Path -LiteralPath $destFull) {
  Fail ("... 'to' already exists in dist; overlays must not replace upstream files ...")
}
if ($declared.ContainsKey($destFull)) {
  Fail ("... 'to' collides with {1} ...")
}

After — collision first

if ($declared.ContainsKey($destFull)) {
  Fail ("... 'to' collides with {1} ...")
}
if (Test-Path -LiteralPath $destFull) {
  Fail ("... 'to' already exists in dist; overlays must not replace upstream files ...")
}

Before — case-insensitive placeholder

json = '{"skill":"SK", ...}'
$json = ($c.json -replace 'SK', $SKILL) -replace 'ABS', ($build -replace '\', '\\')
# -> {"subagent-driven-developmentill": ...}

After

json = '{"skill":"@@SKILL@@", ...}'
$json = ($c.json -creplace '@@SKILL@@', $SKILL) -creplace '@@ABS@@', ($build -replace '\', '\')

Two verification steps the plan got wrong

The leftover worktree was real. Step 4 makes the publisher exit before its own cleanup, so release-exectest stayed checked out in the sibling worktree. git branch -D alone failed with “cannot delete branch 'release-exectest' used by worktree” — confirming the review finding exactly. The explicit git worktree remove --force the plan added is what makes the cleanup work.

The line-ending check was unsound. The plan used git show … | od -c | grep -c '\r', which reported 277 on a file with no CR bytes at all: od -c renders a literal backslash as two characters, so ordinary \t and \n escapes in the awk source satisfy the pattern. Replaced with tr -cd '\r' | wc -c, which counts CR bytes and reports 0 for all three published scripts. Task 8 uses the same command and needs the same correction.

All four observations passed — verified from artifacts, not the transcript

  • 2. The pre-flight scan produced both row types. Three per-pair rows (T1→T2, T1→T3, T2→T3) with producer output against consumer expectation, plus three per-task self-consistency rows. That table cannot be written without every task’s full body, so it is the evidence --plan emitted the whole thing rather than a summary.

The run went past the stop point on its own, completing Task 1 and extracting Task 2 before being interrupted. It added no commits and left nothing outside git-ignored scratch.

Task 8 — Release 6.3.0+fork.2 · 8ca323d

Simplify pass: two findings applied, four skipped with reasons

Four review angles ran in parallel. Three of the four independently flagged the same defect — publish-mysuperpower.ps1 ran git ls-files -s over the whole index a second time purely to ask whether one path is 100755, when $srcExec twenty-five lines above is already exactly that set. Removed. The other applied finding was an awk array named _ignore that nothing ever read, left over from an abandoned generic entity-parsing approach.

Skipped, each for a stated reason rather than an argument:

  • The post-copy existence check was flagged as unreachable under $ErrorActionPreference = "Stop". True today, but the spec requires it by name: the build's other checks are plugin name, skill count and residual namespace, and a silently skipped copy passes all three while shipping a SKILL.md that points at a script which is not there. Removing it would put the build out of compliance with an approved spec to save five lines.
  • 13 full builds per capability-test run (~65s) is a real cost, but the fix is to make Copy-OverlayFiles dot-sourceable — restructuring production code for testability, well outside this diff.
  • "files": [] in the requesting-code-review overlay is inert, but spec-specified and it documents intent: this overlay deliberately ships no files.
  • -OverlaysDir as test-only scaffolding — the reviewer that raised it also called it a defensible compromise, and it is what allows the fail-loud paths to be tested through the real entry point.

Both applied fixes were verified rather than assumed: 63/63 extractor assertions including every entity case, a throwaway publish still chmodding 20 files with the extractor 100755 in both copies, and the declared-intent failure path still refusing to publish a 100644 source.
